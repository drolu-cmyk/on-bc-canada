# Specialization curriculum

The specialization layer extends the Common Core into four connected technical tracks. Each track uses the same learning contract: measurable outcomes, evidence artifacts, human review, safe labs, accessible pathways, and substitution tests for changing tools.

## Track map

| Track | Foundation | Practicum |
| --- | --- | --- |
| Applied AI | `AAI-101` | `AAI-102` |
| Cybersecurity GRC | `GRC-101` | `GRC-102` |
| AI Governance | `AIG-101` | `AIG-102` |
| Cloud | `CLO-101` | `CLO-102` |

## Common design

- Foundations precede advanced application.
- Every module names stable concepts and replaceable implementation tools.
- Every outcome maps to evidence and rubric criteria.
- Every lab uses synthetic, public, or expressly authorized data.
- Every specialization includes critique, revision, and a defensible practicum.
- Attendance remains separate from competency evidence and credential claims.
- Human authorization remains present for safety, accessibility exceptions, assessment appeals, credential decisions, and external claims.

## Evidence pattern

Learners produce a traceable artifact, receive structured feedback, revise the artifact, and explain the decision boundary. The compiler generates learner pages, instructor run-of-show files, safe-lab briefs, rubrics, feedback forms, evidence indexes, and release manifests from the module specifications.

## Tool-change boundary

A model, cloud service, editor, dashboard, or collaboration provider can change without changing the learning outcome. The substitution test in each module records the portable reasoning and evidence standard.
